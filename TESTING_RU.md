# Руководство по тестированию goclip

Это простое руководство для тестировщиков и пользователей, объясняющее, как проверить работу утилиты `goclip` на разных операционных системах (Windows, Linux, macOS) и как правильно отправить отчет об ошибке (баг-репорт).

---

## 1. Где взять программу

Скачайте архив для вашей операционной системы из таблицы в [README.md](README.md#quick-download-nightly-builds):

- **Windows**: `goclip-windows-amd64.zip` (для 64-битных ПК) или `goclip-windows-arm64.zip` (для ARM-планшетов/ноутбуков). Распакуйте архив, внутри будет файл `goclip.exe`.
- **Linux**: `goclip-linux-amd64.tar.gz` (для обычных ПК) или `goclip-linux-arm64.tar.gz` (для Raspberry Pi / ARM).
- **macOS**: `goclip-darwin-arm64.tar.gz` (Apple Silicon: M1/M2/M3/M4) или `goclip-darwin-amd64.tar.gz` (Intel Mac).

---

## 2. Быстрая проверка базовых функций

Откройте терминал (Командную строку / PowerShell / bash / zsh) в папке с распакованным файлом `goclip`.

### А. Проверка версии и справки
```bash
./goclip -version
./goclip -help
```
*Ожидаемый результат:* Программа выводит номер версии и список доступных параметров.

---

### Б. Проверка копирования и вставки текста

#### 1. Копирование текста в буфер:
- **Linux / macOS:**
  ```bash
  echo "Привет, мир 123" | ./goclip
  ```
- **Windows (PowerShell):**
  ```powershell
  "Привет, мир 123" | .\goclip.exe
  ```
- **Windows (CMD):**
  ```cmd
  echo Привет, мир 123 | goclip.exe
  ```

#### 2. Вставка текста из буфера:
- **Любая ОС:**
  ```bash
  ./goclip -o
  ```
*Ожидаемый результат:* В консоли напечатается строка `Привет, мир 123`.

---

## 3. Проверка взаимодействия с другими программами (GUI)

Буфер обмена должен работать сквозным образом между консолью и графическими окнами.

### Сценарий 1: Из браузера/Блокнота в консоль
1. Откройте любой браузер или текстовый редактор (Блокнот, TextEdit, Kate, gedit).
2. Выделите любой фрагмент текста (включая русские буквы и эмодзи 🚀) и скопируйте его стандартным сочетанием клавиш `Ctrl+C` (или `Cmd+C` на Mac).
3. В терминале выполните команду:
   ```bash
   ./goclip -o
   ```
*Ожидаемый результат:* Скопированный в браузере текст отображается в консоли без искажения кодировки.

### Сценарий 2: Из консоли в графическую программу
1. В терминале скопируйте текст в буфер с помощью `goclip`:
   ```bash
   echo "Тестовая строка из терминала 🌟" | ./goclip
   ```
2. Перейдите в текстовый редактор или поле ввода браузера и нажмите `Ctrl+V` (или `Cmd+V` на Mac).
*Ожидаемый результат:* В программу вставляется текст `Тестовая строка из терминала 🌟`.

---

## 4. Проверка специальных режимов

### 1. Удаление завершающего перевода строки (`-rmlastnl`):
```bash
./goclip -o -rmlastnl
```
*Ожидаемый результат:* Текст вставляется без лишнего пустого перевода строки на конце.

### 2. Копирование содержимого файла:
Создайте текстовый файл `test.txt` с несколькими строками текста и выполните:
```bash
./goclip test.txt
./goclip -o
```
*Ожидаемый результат:* Содержимое файла оказывается в буфере обмена.

### 3. Работа в среде без графического сервера (SSH / чистая консоль):
Если на Linux выключить графический сервер или зайти по SSH без проброса X11:
```bash
echo "Текст для локального файла" | ./goclip
./goclip -o
```
*Ожидаемый результат:* `goclip` автоматически использует локальный файловый буфер, текст сохраняется и читается корректно.

---

## 5. Что делать, если что-то работает не так (сбор отладочных логов)

Если текст не копируется, вставляется пустая строка или возникает ошибка, запустите команду с флагом `--debug`:

```bash
# Для записи
echo "Проверка" | ./goclip --debug

# Для чтения
./goclip --debug -o
```

Флаг `--debug` выведет технический блок информации:
- Ваша операционная система и архитектура.
- Состояние переменных окружения графических серверов (`DISPLAY`, `WAYLAND_DISPLAY`).
- Какой драйвер был выбран в качестве активного.
- Список всех обнаруженных в системе драйверов.

---

## 6. Как правильно оформить баг-репорт

Если вы нашли проблему, пожалуйста, откройте Issue на GitHub:
**https://github.com/unxed/goclip/issues**

В сообщении укажите:
1. **Операционную систему и её версию** (например: *Windows 11*, *Ubuntu 24.04 Wayland*, *macOS 14 Sonoma M2*, *Arch Linux X11*).
2. **Какую команду вы выполняли** (например: `echo 123 | goclip`).
3. **Что произошло и что ожидалось** (например: *«В Блокнот вставилась пустая строка, ожидался текст 123»*).
4. **Вывод команды с флагом `--debug`** (скопируйте весь блок текста, который выдала команда `./goclip --debug -o`).
